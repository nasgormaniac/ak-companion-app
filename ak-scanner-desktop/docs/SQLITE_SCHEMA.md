# Desktop SQLite schema (Phase 04)

The new database is `app.getPath('userData')/data/ak-scanner.sqlite`. It is created empty: no legacy rows, IDs, images, or Laravel framework tables are copied. Electron main owns the connection. The schema uses one `cards` table, so `UNIQUE(card_code)` applies across Animal, Strong, and Miracle. Current `PRAGMA user_version` is **2**.

## Table: `cards`

| Column | SQLite type | Rules and meaning |
|---|---|---|
| `id` | `INTEGER PRIMARY KEY` | New desktop row ID. SQLite allocates it; no legacy ID mapping. |
| `category` | `TEXT NOT NULL` | `animal`, `strong`, or `miracle`; category discriminator. |
| `nama` | `TEXT NOT NULL` | Trimmed, 1–255 characters. |
| `rarity` | `TEXT NOT NULL` | Animal: `common`, `bronze`, `silver`, `gold`, `ultra`, `kaiser`; Strong/Miracle: first four. |
| `card_code` | `TEXT NOT NULL UNIQUE` | Exactly eight ASCII bytes: lowercase `bn` plus six printable non-space ASCII characters. Case-sensitive uniqueness across all categories. |
| `image_path` | `TEXT NOT NULL` | Application-generated filename relative to `userData/images/`; repository accepts a 32-character lowercase hex name plus `.jpg` or `.png`. No absolute path or directory separator. Actual image staging and display are a later phase. |
| `gold_attack` | `TEXT NULL` | Animal only: `G`, `T`, `P`. |
| `card_type` | `TEXT NULL` | Animal/Miracle only: `speed`, `multi`, `heavy`; named differently from legacy `type`. |
| `guts_level`, `tech_level`, `power_level` | `INTEGER NULL` | Strong only, each 1–5. |
| `aura` | `TEXT NULL` | Strong only: `none`, `shining`, `defense`, `burning`, `evil`, `forest`, `miracle`. |
| `effect` | `TEXT NULL` | Miracle only: `None`, `Slot Jammer`, `All Big`, `All Doubling`, `All Miracle`, `Lucky Chance`, `Lucky Break`, `All G`, `All T`, `All P`, `Resurrection`, `G Guard`, `T Guard`, `P Guard`, `Mystery Miracle`. |
| `created_at`, `updated_at` | `TEXT NOT NULL` | UTC ISO-like timestamp generated on insert; repository refreshes `updated_at` on update. |

One table-level `CHECK` makes the category-specific fields mutually exclusive and requires the fields appropriate to the chosen category. The database also checks category, name length, code pattern, image filename length/separators, and allowed category values. Main-process repository validation adds specific user-facing errors and checks the stricter image filename pattern. There is no persisted card workflow status. `CONNECTED` and related game states describe the latest in-memory HTTP attempt, not a card record.

## Indexes, relationships, configuration

| Name | Definition | Purpose |
|---|---|---|
| SQLite primary key | `id` | Stable record lookup and tie-breaker. |
| SQLite unique index | `card_code` | Global code uniqueness. |
| `cards_category_created_idx` | `(category, created_at DESC, id DESC)` | Category pages, newest first. |
| `cards_category_rarity_idx` | `(category, rarity)` | Category and rarity filter. Rarity sort uses an explicit rank expression because alphabetic order is wrong. |

There are no relational child tables or foreign keys in version 2. Images remain files referenced by owned filenames; this is not a SQL relationship. The connection still enables `PRAGMA foreign_keys=ON` so future relationships are enforced per connection. The outbound game port remains in `userData/data/game-settings.json`, with default 9876; theme settings belong to the later UI phase. No `users`, `sessions`, cache, queue, password-reset, or Laravel migration table exists.

## Classification of legacy fields

Each card-table column is classified below. The same common columns in `animals`, `strongs`, and `miracles` have the same treatment.

| Legacy field | Classification | Desktop decision |
|---|---|---|
| `id` | TRANSFORMED | New `INTEGER PRIMARY KEY`; values start anew and are not imported. |
| `nama` | PRESERVED | Same meaning, trimmed and limited to 255 characters. |
| `rarity` | PRESERVED | Same category-specific values; database enforces them. |
| `card_code` | TRANSFORMED | Same barcode meaning and compatible punctuation, now one global unique constraint and one consistent validation rule. |
| `image` | TRANSFORMED | Required `image_path` stores an app-generated relative filename, not a Laravel public-storage path. |
| `created_at`, `updated_at` | TRANSFORMED | Non-null UTC timestamps generated by the desktop app; old timestamps are not copied. |
| Animal `gold_attack` | PRESERVED | Same `G/T/P` options. |
| Animal/Miracle `type` | TRANSFORMED | Same `speed/multi/heavy` values, stored as `card_type`. |
| Strong `guts_level`, `tech_level`, `power_level` | TRANSFORMED | Same 1–5 meaning, stored as SQLite integers rather than legacy strings. |
| Strong `aura` | PRESERVED | Same seven options. |
| Miracle `effect` | PRESERVED | Same fifteen options, including case and spaces. |

The legacy `users` fields (`id`, `name`, `email`, `email_verified_at`, `password`, `remember_token`, timestamps), `password_reset_tokens` fields (`email`, `token`, `created_at`), `sessions` fields (`id`, `user_id`, `ip_address`, `user_agent`, `payload`, `last_activity`), `cache`/`cache_locks` fields, `jobs`/`job_batches`/`failed_jobs` fields, and Laravel `migrations` fields (`id`, `migration`, `batch`) are **OBSOLETE** for this single-user desktop product. No legacy field remains **UNCLEAR** for the target card schema. Rarity rank is **DERIVED** in list queries from `rarity`; it is not stored.
